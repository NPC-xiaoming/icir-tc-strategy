# 行情获取、暂估和补算

2026-10-16 在 GitHub Ubuntu / AKShare 1.18.81 实测：东方财富个股历史接口对 000001、600519 报 `RemoteDisconnected`，腾讯与新浪能返回日期完整的行情。不能仅据此判定具体网络策略或限流原因。旧程序吞掉异常，并将全部缺失持仓按 0% 入账，导致 14、15 日报告无效。

## 用户选择：保留现有收益口径

继续采用东方财富后复权涨跌幅代理；不是更换为前复权收益，也不改变历史回测。备用源腾讯、新浪须至少有 3 个历史重叠收益，与东方财富最近最多 20 个重叠收益逐日差异不超过 0.0001（1 个基点）。没有可信参考数据或校验失败时不采用备用数据。历史一致性检查不能保证不同供应商未来复权算法完全一致，报告须保留来源。

备用收益从同一来源的连续两个交易日后复权收盘价计算，不跨来源拼接价格，不把多日累计收益当作单日收益。新浪/新版腾讯的换手率从比例换算成百分比。缺少换手率的旧版腾讯数据不能用于需要该字段的因子计算。

## 请求和保存

- 东方财富 → 腾讯 → 新浪；每个源异常/空结果最多尝试 2 次，间隔带随机等待，并发最多 3（配置为 2）。
- 一个源连续多只股票请求失败后，本次任务停止向该源请求；下一次任务重新尝试。不是绕过限流或访问控制。
- 无足够可信参考时，不重复请求无法通过校验的备用数据。已完整缓存的股票日期不重复下载。行情保存在 `state/market_history.parquet`，按来源和复权方式分开，每组保留最近 600 行。
- 指数使用东方财富 → 腾讯 → 新浪，验证请求的所有交易日和收盘价。交易日历失败时使用仍覆盖今天的缓存。
- 每只股票/每个来源的异常、实际选用来源、逐日缺失持仓及权重保存在运行产物 `logs/data_quality.json`。
- 失败任务仅提交有效行情和交易日历缓存，不提交估值账本或日报；产物中保留完整日志。

## 记账保护与纠错

- 全部持仓缺行情，或缺失持仓权重超过 5%：报错，正式账本不前进。
- 缺失权重不超过 5%：允许 0% 暂估，但日报顶部明确标注暂估，保存 `state/valuation_checkpoint.json` 和逐股票、逐日期缺失清单。
- 只要存在检查点，即使该日以前显示运行成功，也从暂估前账本重新计算所有后续交易日，重写各日独立报告。
- 有待补齐持仓行情时不调仓，以免暂估持仓污染调仓计算。补齐后才恢复调仓。
- 全部补齐并成功保存账本后删除检查点。重复执行不会重复扣费或复利。
